00 · G-A-V-EX

四大支柱，一条可信执行链Four pillars. One trusted execution chain.

Guarded Audit & Verifier-gated Execution
G-A-V-EX 把边界、对抗审计、独立否决与阶梯执行组合成可追溯的工程协议。G-A-V-EX brings guarded boundaries, adversarial audit, independent vetoes and staged execution into one traceable engineering protocol.

G

Guarded Write-Scopes

受保护的写入边界：先声明文件白名单，逐对验证互斥；越界即否决，热点文件只有一个负责人。Declare file allowlists before dispatch, verify pairwise disjointness and veto out-of-scope writes. Every hot file has one owner.

A

Adversarial Cross-Audit

异构对抗会审：独立盲审、匿名交叉质询，以真实探针关闭分歧，而非靠投票凑共识。Heterogeneous blind reviews and anonymous cross-examination close disagreements with real probes, not a majority vote.

V

Verifier Veto Gates

独立验工否决：全新上下文、只读、真实入口，全量回归不过就打回，Worker 不得给自己签发 PASS。A fresh, read-only verifier tests real entry points and the full regression suite. Workers can never sign their own PASS.

EX

Execution Pipeline

阶梯执行流水线：先锁定方案，同阶安全并行，验工放行后才解锁下一阶；事件驱动等待，证据持续落盘。Lock the plan, parallelize safely within each step and unlock the next only after verification. Wait on events and persist evidence as work proceeds.

Gavel 法槌 + Execution 执行：法槌代表独立裁决与一票否决，Execution 代表受门禁约束的真实施工。先守界、后执行；先有证据、再落槌，不把“已完成”当作验收。Gavel + Execution: the gavel stands for independent judgment and veto power; execution means real work constrained by those gates. Guard first, execute next. Evidence comes before the verdict — “done” is not proof.

成功终态为 GAVEX_FINAL_ACCEPTED；无法安全继续时签发 GAVEX_ESCALATED 并转人工，绝不伪装通过。每次裁决与证据写入 .gavex/ledger.md。Success ends with GAVEX_FINAL_ACCEPTED. If safe progress is impossible, issue GAVEX_ESCALATED for human intervention — never a false pass. Record verdicts and evidence in .gavex/ledger.md.

01 · Why

为什么单次巨型 Prompt 必败Why a single mega-prompt fails

问题不在模型不够聪明，而在执行结构：没有阶梯、没有边界、没有独立裁判。The model isn't the problem — the execution structure is: no stages, no boundaries, no independent referee.

✕单次巨型 Prompt / 普通子代理群发Mega-prompt / naive sub-agent fan-out

"一次性把 12 个模块全部改完，写测试并确认 100% 通过Change all 12 modules at once, write tests and confirm 100% passing"
  • 1
    一锅端大爆炸Big-bang blast radius

    底座没稳，后续模块全部建立在错误假设上盲改。Foundations aren't stable, so every later module is built on wrong assumptions.

  • 2
    并发踩踏Write-Scope collisions

    多个 Worker 同时改同一个文件、争同一个锁，互相覆盖。Several workers edit the same file or lock and silently overwrite each other.

  • 3
    运动员兼裁判Self-grading hallucination

    Worker 跑个假测试就宣称完成，主代理直接转述，用户一跑全崩。Workers run a fake test, claim "done", the main agent relays it — and it breaks for the user.

✓GAVEX 阶梯门禁 + 独立验工GAVEX stage gates + independent verification

Step 1 → STEP_1_VERIFIED_PASS → Step 2 → … → GAVEX_FINAL_ACCEPTED
  • 1
    阶梯扣留Stage-gated planning

    Step K 未拿到独立签发的 PASS 印章前，Step K+1 一律锁定。Step K+1 stays locked until Step K earns an independently signed PASS.

  • 2
    非重叠 Write-Scope 并行Non-overlapping parallelism

    同阶 Worker 白名单两两求交为空，热点文件唯一归属。Same-step Write-Scopes have empty pairwise intersections; hot files have one owner.

  • 3
    专职独立 VerifierDedicated independent verifier

    全新上下文、只读、真实入口实跑；有瑕疵就打回，直到全绿。Fresh context, read-only, real entry points; any defect bounces back until all green.

    03 · Veto gates

    四大一票否决硬门禁Four hard veto gates

    任一门禁失败，整阶签发 STEP_K_REJECTED，缺陷精准归属到 Worker K-X 定点重修；复核必须全量重跑。Any failing gate rejects the whole step with STEP_K_REJECTED; the defect is routed to the owning Worker K-X, and the recheck reruns everything.

    G1VETO

    真实入口 · 拒绝白盒注入Real entry points only

    必须从 CLI / HTTP / UI / 公开 API 端到端触发；禁止改内存状态、mock 被测对象或手写假数据。Trigger end-to-end through CLI / HTTP / UI / public API. No poking in-memory state, no mocking the subject, no hand-made fixtures as proof.

    curl -sf :8080/api/sessions
pnpm e2e --reporter=line
    G2VETO

    多视口 × 深浅色真实渲染Multi-viewport × theme render

    涉及前端：≥ 3 个视口 × 深浅两色真实渲染截图，核验溢出、几何对齐、对比度与控制台报错。For UI: real renders at ≥ 3 viewports × light/dark, checking overflow, geometry, contrast and console errors.

    # 390 / 1024 / 1440 × dark / light
console.error = 0
overflow-x    = 0px
    G3VETO

    Dry-run 零破坏Dry-run, zero damage

    涉及配置、数据库、迁移或外部服务，必须先干跑并对比前后快照，确认无破坏性写入。For config, databases, migrations or external services: dry-run first and diff snapshots to prove no destructive writes.

    # expect: 0 destructive DDL
migrate --dry-run
# expect: 0 to destroy
terraform plan
    G4VETO

    需求不缩水No silent scope cuts

    逐条映射原始需求与证据；任何「先跳过」「改成 TODO」「降级占位」都判定失败。Map every requirement to evidence. “Skip for now”, “TODO” or placeholder downgrades are failures.

    requirements ↔ evidence: 9/9

    05 · Install

    跨平台一键安装One-line install, any agent

    GAVEX 是一个单文件 SKILL.md，工作区入口是 skills/gavex/SKILL.md，源码放在 ~/Developer/GAVEX，运行台账写入 .gavex/ledger.md。只依赖 spawn / wait / run 三种原语；没有子代理能力的平台自动降级为单 Agent 串行模式。GAVEX is a single SKILL.md installed at skills/gavex/SKILL.md, with sources in ~/Developer/GAVEX and the run ledger at .gavex/ledger.md. It relies only on spawn / wait / run. Platforms without sub-agents fall back to a single-agent serial mode.
